# Pixo — архитектура SVG-компонентов

Краткое описание того, как редактор хранит SVG-элементы, извлекает их из файлов и повторно использует на холсте.

## Хранение

Рабочая область сохраняется в IndexedDB: база `pixo-workspace`, хранилище `workspace`. Данные разделены по ключам:

- `assets` — импортированные SVG-файлы и компоненты пользовательской библиотеки;
- `objects` — объекты текущего холста;
- `projects` — сохранённые проекты вместе с их объектами;
- `active-project-id` — открытый проект;
- `service-library-seeded` — признак заполнения встроенной библиотеки.

Настройки интерфейса хранятся в `localStorage`. Старые данные из `localStorage` переносятся в IndexedDB при загрузке рабочей области.

SVG-ассет содержит метаданные (`id`, название, категория, размеры, `viewBox`, источник) и SVG-разметку в поле `markup`. Экземпляр на холсте — это `CanvasObject`: SVG-ассет с уникальным `objectId`, координатами, размерами, поворотом и состоянием слоя. Вложенность групп задаётся через `frameId`, `isFrame` и `isGroup`.

Основные определения типов находятся в [`src/types/svg.ts`](src/types/svg.ts), проекты — в [`src/types/project.ts`](src/types/project.ts), доступ к IndexedDB — в [`src/features/storage/workspaceStorage.ts`](src/features/storage/workspaceStorage.ts).

## Извлечение SVG-элементов

1. `getSvgStructure` разбирает SVG в дерево элементов. Для каждого узла сохраняется путь из индексов дочерних элементов.
2. `extractSvgNode` находит выбранный узел, копирует его вместе с необходимыми группами-предками и сохраняет используемые определения и стили: `defs`, `style`, маски, фильтры, градиенты и другие ресурсы. Основные наследуемые SVG-атрибуты переносятся на извлечённый фрагмент.
3. Результат сохраняется в библиотеке как ассет с собственным `id` и ссылкой `sourceFileId` на исходник. Исходный SVG при этом не изменяется.

Когда импортированный SVG разделяется на объекты, границы узлов измеряются через SVG DOM (`getBBox` и `getScreenCTM`) и переводятся в систему координат исходного `viewBox`.

Реализация разбора и извлечения находится в [`src/features/svg-import/SvgStructure.ts`](src/features/svg-import/SvgStructure.ts); создание компонентов и объектов холста — в [`src/App.tsx`](src/App.tsx).

## Повторное использование

Добавление ассета на холст создаёт новый `CanvasObject` с уникальным `objectId`. Разметка `markup` используется повторно, а положение и трансформации хранятся у конкретного экземпляра отдельно. Поэтому один компонент можно размещать на холсте несколько раз.

При добавлении импортированного исходника редактор может разобрать его на отдельные векторные объекты и создать группу. Связь между группой и её элементами хранится через `frameId`.

Перед отображением и экспортом `namespaceSvgIds` добавляет уникальное пространство имён к внутренним SVG `id` и ссылкам на них. Это предотвращает конфликты градиентов, масок и других SVG-ресурсов между экземплярами. Реализация находится в [`src/features/export/SvgExporter.ts`](src/features/export/SvgExporter.ts).

## Поток данных

```text
Импорт SVG → IndexedDB (assets) → просмотр дерева → извлечение элемента
                                             ↓
                                      компонент библиотеки
                                             ↓
                                      CanvasObject в проекте
                                             ↓
                               отрисовка или SVG-экспорт
```
